# 🗄️ Plan de Integración y Modelado Backend

Aunque actualmente el proyecto se encuentra enfocado en la experiencia de usuario (frontend) y la presentación institucional, este documento define la hoja de ruta para la conexión con servicios backend y bases de datos.

---

## 1. Arquitectura de Autenticación Propuesta
- **Mecanismo:** JSON Web Tokens (JWT) almacenados en cookies seguras `HttpOnly`, `Secure`, y `SameSite=Strict` para mitigar ataques XSS y CSRF.
- **Rutas de API (Route Handlers en Next.js):**
  - `POST /api/auth/login`: Validación de credenciales y expedición de tokens de sesión.
  - `POST /api/auth/logout`: Invalidación de cookies de sesión.
  - `GET /api/auth/me`: Verificación de sesión activa y carga de perfil de usuario.

---

## 2. Modelo de Datos Proyectado (Entidad Usuario)
```typescript
export interface UserEntity {
  readonly id: string;
  readonly email: string;
  readonly fullName: string;
  readonly role: "STUDENT" | "TEACHER" | "ADMIN";
  readonly avatarUrl?: string;
  readonly currentLevel: "A1" | "A2" | "B1" | "B2" | "C1";
  readonly isActive: boolean;
  readonly createdAt: string;
  readonly updatedAt: string;
}
```

---

## 3. Estados del Formulario de Inicio de Sesión
El formulario actual (`LoginForm.tsx`) ya implementa la máquina de estados local para la interacción:
1. **Estado Inicial:** Campos limpios, listo para captura de datos.
2. **Validación Cliente:** Verificación de formato de correo y longitud mínima de contraseña (6 caracteres).
3. **Estado Enviando (`isSubmitting: true`):** Botón deshabilitado con spinner giratorio animado.
4. **Feedback Visual:** Alertas de error (rojo con ícono de advertencia) o éxito (verde esmeralda con mensaje de bienvenida).
