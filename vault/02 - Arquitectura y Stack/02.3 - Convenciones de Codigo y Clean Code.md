# 📐 Convenciones de Código y Clean Code

El proyecto adopta estrictos lineamientos de calidad de software inspirados en los principios **SOLID**, la filosofía de diseño ingenieril de **Emil Kowalski** y los estándares de **Clean Code**.

---

## 1. Principios Aplicados

### A. Single Responsibility (Responsabilidad Única)
- Cada componente tiene una tarea precisa.
  - `Navbar.tsx` se encarga exclusivamente de la navegación y su detección de scroll.
  - `Iridescence.tsx` gestiona el ciclo de vida del renderizador WebGL y shaders.
  - `AnimatedBackground.tsx` actúa como integrador entre el tema activo (`next-themes`) y la capa de visualización de fondo.
  - `LoginForm.tsx` maneja el estado de los campos, validaciones y feedback de autenticación.

### B. Tipado Estricto (Strict TypeScript)
- Prohibido el uso de `any` implícito o explícito.
- Tipado exhaustivo de estados, props e interfaces:
  ```typescript
  interface LoginFormState {
    readonly email: string;
    readonly password: string;
    readonly rememberMe: boolean;
  }
  ```
- Propiedades inmutables con `readonly` para evitar efectos colaterales.

### C. Limpieza del DOM y Ciclo de Vida en React 19
- En hooks `useEffect`, siempre se retorna una función de limpieza (*cleanup function*).
- Validación de presencia de nodos antes de invocar métodos destructivos:
  ```typescript
  // Previene DOMException en React 19 StrictMode:
  if (gl.canvas && ctn.contains(gl.canvas)) {
    ctn.removeChild(gl.canvas);
  }
  gl.getExtension('WEBGL_lose_context')?.loseContext();
  ```

---

## 2. Convenciones de Estilo y Naming
1. **Archivos de Componentes:** `PascalCase.tsx` (ej. `ThemeToggle.tsx`).
2. **Archivos de Utilidad / Configuración:** `kebab-case.ts` o `camelCase.ts`.
3. **Constantes Inmutables:** `UPPER_SNAKE_CASE` (ej. `INITIAL_FORM_STATE`).
4. **Funciones de Eventos:** Prefijo `handle` (ej. `handleFormSubmit`, `handleMouseMove`).
5. **Funciones de Estado Booleano:** Prefijos `is`, `has`, `should` (ej. `isScrolled`, `isSubmitting`).
